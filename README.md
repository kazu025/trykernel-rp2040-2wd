# TryKernel RP2040 2WD

Raspberry Pi Pico（RP2040）とTryKernelを使って、2輪駆動ロボットを制御する学習用プロジェクトです。
UARTコンソールから左右のモーターの回転方向とPWMデューティ比を指定できます。

TryKernelに追加してきた同期・通信・周期イベントなどの機能を、実際のハードウェア制御へ応用することを目的としています。Pico SDKは使用せず、RP2040のレジスタを直接操作しています。

## 元のプロジェクトと今回の構成

本プロジェクトは、[TryKernel RP2040 Console](https://github.com/kazu025/trykernel-rp2040-console)を元にしています。
元のプロジェクトでは、RTOS機能の拡張に加え、温度センサー、MPU6050、電力モニター、LCD、SPI Flashなどを使った実験を行っていました。

今回はモーター制御へ進むため、UART・LED・モーターに必要な構成へ整理しました。
センサー未接続でも起動できるようにセンサー関連タスクを起動対象から外し、使用しないコンソールコマンドも削除しています。
古いセンサー用ソースは参考用として残っていますが、現在のMakefileではビルド対象外です。

TryKernelの原典は、CQ出版社『Interface』2023年7月号「ラズパイPicoで1500行 ゼロから作るOS」のシングルコア版Try Kernelです。

## RTOS機能とその応用

原典から引き継いだ機能と、これまでの拡張を含め、次の機能を備えています。

- 優先度に基づくタスク実行とPendSVによるコンテキスト切り替え
- タスク生成・起動・終了、遅延、起床待ち・起床
- セマフォ、イベントフラグによる同期
- ミューテックスと動的優先度継承
- 固定長メッセージキューによるタスク間通信
- タイムアウト付き待ち処理
- SysTickによる10ms刻みの時間管理
- 周期イベントの生成・開始・停止・削除・状態参照

現在の2WDアプリケーションでは、UART受信通知にイベントフラグ、UART送信の保護やLEDの周期通知にセマフォを使用しています。
周期イベントはLED制御で使用しており、モーターの周期的な走行制御は今後の拡張です。

## 現在できること

- 左右モーターの独立した正転・逆転・停止
- 左右モーターを組み合わせた前進・後退・左右旋回
- 0〜100のPWMデューティ指定（PWM周波数は20kHz）
- UARTコマンドによる操作と通信状態の確認
- オンボードLEDの点灯・消灯・点滅
- 起動時のモーター停止

ホビー用5Vモーターでの単体確認後、車体のモーターに接続し、左右とも`forward`指定で車体が前進することを実機確認しました。未使用コマンドとビルド対象の整理後も動作確認済みです。

## 使用ハードウェア

| 部品 | 今回の構成 |
|---|---|
| マイコン | Raspberry Pi Pico（RP2040、通常版） |
| 車体 | 秋月電子で購入した2WD Mini Smart Robot Mobile Platform Kit for education |
| モーター | 車体付属のDCギヤードモーター（定格3〜6V） |
| モータードライバ | AE-DRV8835-S |
| モーター電源 | 単3形充電池3本（実測約3.8V） |
| 電源平滑用 | VMとGNDの間に電解コンデンサーを接続 |
| 書き込み・UART | Raspberry Pi Debug Probe |

PicoはUSBから給電し、モーターは別の電池から給電します。Pico、ドライバ、モーター電源のGNDは共通にします。

## 配線

### PicoとDRV8835

DRV8835のMODEを3.3Vへ接続し、PHASE/ENABLEモードで使用します。
A側を左モーター、B側を右モーターに割り当てています。

| DRV8835端子 | 接続先 | 用途 |
|---|---|---|
| VCC | Pico 3V3 OUT（物理36番） | ロジック電源 |
| MODE | Pico 3V3 OUT（物理36番） | PHASE/ENABLEモード |
| GND | Pico GNDと電池のマイナス | 共通GND |
| VM | モーター用電池のプラス | モーター電源 |
| AIN1 | GPIO8（物理11番） | 左の回転方向 |
| AIN2 | GPIO9（物理12番） | 左のPWM |
| BIN1 | GPIO10（物理14番） | 右の回転方向 |
| BIN2 | GPIO11（物理15番） | 右のPWM |
| AOUT1 / AOUT2 | 左モーターの2端子 | モーター出力 |
| BOUT1 / BOUT2 | 右モーターの2端子 | モーター出力 |

電解コンデンサーはVMとGNDの間に並列に接続します。プラスをVM、マイナスをGNDへ接続し、電源電圧を上回る耐圧のものを使用します。モーター電源をPicoの3V3端子へ接続しないでください。

`forward`の実際の回転方向は、モーターの取り付け方と出力端子への配線で決まります。左右それぞれで前進方向になるよう確認してください。

### UART

| Pico | Debug Probeまたは3.3V USB-UART変換器 |
|---|---|
| GPIO0 / TX（物理1番） | RX |
| GPIO1 / RX（物理2番） | TX |
| GND（物理3番など） | GND |

通信設定は**115200bps、8N1、フロー制御なし**です。
コンソールはUART0を使用します。PicoのUSB端子をUSBシリアルコンソールとして使う構成ではありません。

## ビルドと書き込み

GNU Make、Arm GNU Toolchain（`arm-none-eabi-gcc`など）、RP2040対応のOpenOCDを用意してください。ホストテストにはCコンパイラ（`cc`）も必要です。

```bash
git clone https://github.com/kazu025/trykernel-rp2040-2wd.git
cd trykernel-rp2040-2wd
make
```

既存の作業ディレクトリで作り直す場合は、次のように実行します。

```bash
make clean
make
```

主な生成物は`build/tkv.elf`、`build/tkv.bin`、`build/tkv.hex`です。現在のMakefileはUF2を生成しません。

Debug ProbeのSWDをPicoのSWCLK・SWDIO・GNDへ接続し、Picoへ給電した状態で書き込みます。

```bash
make flash
```

このターゲットはOpenOCDの`cmsis-dap.cfg`と`rp2040.cfg`を使用し、書き込み・検証・リセットを行います。

## UARTでの操作

minicomなどでDebug Probeのシリアルポートを開きます。デバイス名は環境に合わせて変更してください。

```bash
minicom -D /dev/ttyACM0 -b 115200
```

ハードウェア・ソフトウェアのフロー制御は両方とも無効にします。
起動時には、次のメッセージが表示されます。

```text
TryKernel 2WD: UART / LED / motor ready
```

### コマンド一覧

| コマンド | 内容 |
|---|---|
| `help` / `h` | コマンド一覧 |
| `status` | LEDモード、UARTオーバーフローや割り込み回数など |
| `echo hello` | 引数を表示 |
| `print` | 出力テスト |
| `led on` / `led off` / `led blink` | オンボードLED操作 |
| `motor left forward 50` | 左モーターを正転、デューティ指定50 |
| `motor right reverse 30` | 右モーターを逆転、デューティ指定30 |
| `motor left stop` / `motor right stop` | 片側を停止 |
| `motor stop` | 両側を停止 |
| `drive forward 50` | 両輪を前進 |
| `drive reverse 50` | 両輪を後退 |
| `drive left 40` / `drive right 40` | 左右へ旋回 |
| `drive stop` | 両輪を停止 |
| `drive forward 30 500` | 速度30で500msだけ前進して自動停止 |

数値は回転速度の測定値ではなく、PWMのデューティ指定です。50を指定しても最高回転数の半分になるとは限りません。小さい値ではモーターが始動しない場合もあります。

走行時間をミリ秒で指定すると、指定時間後に自動停止します。指定できる時間は0〜60000msです。
時間指定中はUART受信タスクが待機するため、別のコマンドによる途中停止はできません。短い時間から試し、緊急停止が必要な場合は電源を切れる状態で確認してください。

### 両輪を前進させる例

最初は車輪を浮かせて回転方向と停止を確認してください。

```text
motor left forward 50
motor right forward 50
```

停止するときは、次を入力します。

```text
motor stop
```

左右への指令は順番に実行されます。現在は両輪を同時に更新する走行コマンドや、通信が途絶えた際の自動停止機能はありません。モーターは停止指令などで設定を変えるまで動作を続けます。

## ソフトウェア構成

| ファイル | 役割 |
|---|---|
| `user/usermain.c` | モーターなどの初期化とUART・LEDタスクの起動 |
| `user/command.c` | コマンド解析と各操作の呼び出し |
| `user/motor.c` / `user/motor.h` | 左右モーターの方向・デューティ設定・停止 |
| `drivers/pwm.c` / `drivers/pwm.h` | RP2040ハードウェアPWMの設定 |
| `drivers/uart.c` | UART0ドライバと受信割り込み |
| `user/task_uartrx.c` | 受信通知を待ち、コンソール入力を処理 |
| `user/uart_tx.c` / `user/task_uarttx.c` | 送信キューと送信タスク |
| `user/task_led.c` | 周期イベントとセマフォを使ったLED制御 |
| `kernel/cyclic.c` | 周期イベントの管理 |

アプリケーションで起動するタスクはUART受信・UART送信・LEDの3つです。
モーター専用タスクはなく、UART受信タスク内のコマンド処理から方向とPWM設定を変更します。波形の生成はRP2040のPWMハードウェアが継続して行います。

```text
UART受信割り込み → イベント通知 → UART受信タスク
                                      ↓
                                 コマンド解析
                                      ↓
                              モーター方向・PWM設定

SysTick → 周期ハンドラ → セマフォ通知 → LEDタスク
```

LED用の周期ハンドラは100msごとにセマフォを通知します。点滅モードでは10回分の通知を待ち、約1秒ごとにLEDを反転します。周期ハンドラは割り込み内で動作するため、通知だけを行い、LED操作はタスク側で実行します。

## テスト

```bash
make test-cyclic test-mutex
```

周期イベントとミューテックスのホストテストです。割り込み・コンテキスト切り替えを模擬してカーネルのロジックを確認します。実際のSysTick割り込みやPWM出力、配線、モーター動作は検証しないため、実機確認も別途行います。

## 今後の予定

- 前進・後退・左右旋回をまとめた走行コマンド
- 一定時間の走行と自動停止
- 周期イベントを使った加速・減速
- 左右の走行差の調整
- センサー入力とタスク間通信を組み合わせた走行制御
