# TryKernel RP2040 2WD

Raspberry Pi Pico（RP2040）とTryKernelを使って、2輪駆動ロボットを制御する学習用プロジェクトです。
UARTコンソールから左右のモーターの回転方向とPWMデューティ比を指定できます。

TryKernelに追加してきた同期・通信・周期イベントなどの機能を、実際のハードウェア制御へ応用することを目的としています。Pico SDKは使用せず、RP2040のレジスタを直接操作しています。

## 元のプロジェクトと今回の構成

本プロジェクトは、[TryKernel RP2040 Console](https://github.com/kazu025/trykernel-rp2040-console)を元にしています。
元のプロジェクトでは、RTOS機能の拡張に加え、温度センサー、MPU6050、電力モニター、LCD、SPI Flashなどを使った実験を行っていました。

2WD向けにUART・LED・モーターを中心とする構成へ整理し、その後VL53L1Xの距離測定とMPU系ジャイロの表示・補正を追加しました。
温度センサー、電力モニター、LCD、SPI Flashなどの旧ソースは参考用として残していますが、現在はビルド・起動対象から外しています。
距離センサーが未接続でもコンソールは起動しますが、測距できない間は前進・旋回を許可しません。ジャイロは`gyro`コマンド実行時に初期化します。

TryKernelの原典は、CQ出版社『Interface』2023年7月号「ラズパイPicoで1500行 ゼロから作るOS」のシングルコア版Try Kernelです。

## RTOS機能とその応用

原典から引き継いだ機能と、これまでの拡張を含め、次の機能を備えています。

- 優先度に基づくタスク実行とPendSVによるコンテキスト切り替え
- タスク生成・起動・終了、遅延、起床待ち・起床
- セマフォ、イベントフラグによる同期
- ミューテックスと動的優先度継承
- 固定長メッセージキューによるタスク間通信
- タイムアウト付き待ち処理
- SysTickによる10ms刻みの時間管理
- 周期イベントの生成・開始・停止・削除・状態参照

現在の2WDアプリケーションでは、UART受信通知にイベントフラグ、UART送信の保護やLEDの周期通知にセマフォを使用しています。
周期イベントはLED制御（100ms周期）とモーターの加減速（50ms周期）に使用しています。各周期ハンドラはセマフォを通知し、ハードウェアの更新はタスク側で行います。

## 現在できること

- 左右モーターの独立した正転・逆転・停止
- 左右モーターを組み合わせた前進・後退・左右旋回
- 0〜100のPWMデューティ指定（PWM周波数は20kHz）
- UARTコマンドによる操作と通信状態の確認
- VL53L1Xによる距離測定と5点移動平均
- 測距値が200 mm以下になったときのモーター自動停止
- 周期イベントによる走行指令の段階的な加減速
- MPU系ジャイロのXYZ角速度表示と静止時のゼロ点補正
- オンボードLEDの点灯・消灯・点滅
- 起動時のモーター停止

ホビー用5Vモーターでの単体確認後、車体のモーターに接続し、左右とも`forward`指定で車体が前進することを実機確認しました。未使用コマンドとビルド対象の整理後も動作確認済みです。

## 使用ハードウェア

| 部品 | 今回の構成 |
|---|---|
| マイコン | Raspberry Pi Pico（RP2040、通常版） |
| 車体 | 秋月電子で購入した2WD Mini Smart Robot Mobile Platform Kit for education |
| モーター | 車体付属のDCギヤードモーター（定格3〜6V） |
| モータードライバ | AE-DRV8835-S |
| モーター電源 | 単3形充電池3本（実測約3.8V） |
| 電源平滑用 | VMとGNDの間に電解コンデンサーを接続 |
| 距離センサー | 秋月電子 AE-VL53L1X |
| ジャイロ基板 | MPU-6050表記の基板（実機のWHO_AM_Iは0x70、MPU-6500相当） |
| 書き込み・UART | Raspberry Pi Debug Probe |

PicoはUSBから給電し、モーターは別の電池から給電します。Pico、ドライバ、モーター電源のGNDは共通にします。

## 配線

### PicoとDRV8835

DRV8835のMODEを3.3Vへ接続し、PHASE/ENABLEモードで使用します。
A側を左モーター、B側を右モーターに割り当てています。

| DRV8835端子 | 接続先 | 用途 |
|---|---|---|
| VCC | Pico 3V3 OUT（物理36番） | ロジック電源 |
| MODE | Pico 3V3 OUT（物理36番） | PHASE/ENABLEモード |
| GND | Pico GNDと電池のマイナス | 共通GND |
| VM | モーター用電池のプラス | モーター電源 |
| AIN1 | GPIO8（物理11番） | 左の回転方向 |
| AIN2 | GPIO9（物理12番） | 左のPWM |
| BIN1 | GPIO10（物理14番） | 右の回転方向 |
| BIN2 | GPIO11（物理15番） | 右のPWM |
| AOUT1 / AOUT2 | 左モーターの2端子 | モーター出力 |
| BOUT1 / BOUT2 | 右モーターの2端子 | モーター出力 |

電解コンデンサーはVMとGNDの間に並列に接続します。プラスをVM、マイナスをGNDへ接続し、電源電圧を上回る耐圧のものを使用します。モーター電源をPicoの3V3端子へ接続しないでください。

`forward`の実際の回転方向は、モーターの取り付け方と出力端子への配線で決まります。左右それぞれで前進方向になるよう確認してください。

### I²Cセンサー

VL53L1Xとジャイロ基板は、GP4・GP5のI²C0を共有します。配線変更はUSBとモーター電源を切ってから行います。

| センサー端子 | Picoの接続先 |
|---|---|
| VCC / 電源入力 | 3V3 OUT（物理36番） |
| GND | 共通GND（物理38番など） |
| SDA | GP4（物理6番） |
| SCL | GP5（物理7番） |
| ジャイロのAD0 | GND |
| ジャイロのXDA・XCL・INT | 未接続 |

`i2cscan`ではVL53L1Xが`0x29`、ジャイロが`0x68`で検出されています。I²Cアドレスと識別レジスタWHO_AM_Iは別の値です。今回のジャイロはWHO_AM_Iが`0x70`で、[MPU-6500の識別値](https://invensense.tdk.com/wp-content/uploads/2015/02/MPU-6500-Register-Map2.pdf)と一致します。ドライバはMPU-6050（0x68）とMPU-6500（0x70）の識別値を受け付けます。

### UART

| Pico | Debug Probeまたは3.3V USB-UART変換器 |
|---|---|
| GPIO0 / TX（物理1番） | RX |
| GPIO1 / RX（物理2番） | TX |
| GND（物理3番など） | GND |

通信設定は**115200bps、8N1、フロー制御なし**です。
コンソールはUART0を使用します。PicoのUSB端子をUSBシリアルコンソールとして使う構成ではありません。

## ビルドと書き込み

GNU Make、Arm GNU Toolchain（`arm-none-eabi-gcc`など）、RP2040対応のOpenOCDを用意してください。ホストテストにはCコンパイラ（`cc`）も必要です。

```bash
git clone https://github.com/kazu025/trykernel-rp2040-2wd.git
cd trykernel-rp2040-2wd
make
```

既存の作業ディレクトリで作り直す場合は、次のように実行します。

```bash
make clean
make
```

主な生成物は`build/tkv.elf`、`build/tkv.bin`、`build/tkv.hex`です。現在のMakefileはUF2を生成しません。

Debug ProbeのSWDをPicoのSWCLK・SWDIO・GNDへ接続し、Picoへ給電した状態で書き込みます。

```bash
make flash
```

このターゲットはOpenOCDの`cmsis-dap.cfg`と`rp2040.cfg`を使用し、書き込み・検証・リセットを行います。

## UARTでの操作

minicomなどでDebug Probeのシリアルポートを開きます。デバイス名は環境に合わせて変更してください。

```bash
minicom -D /dev/ttyACM0 -b 115200
```

ハードウェア・ソフトウェアのフロー制御は両方とも無効にします。
起動時には、次のメッセージが表示されます。

```text
TryKernel 2WD: UART / LED / motor ready
```

### コマンド一覧

| コマンド | 内容 |
|---|---|
| `help` / `h` | コマンド一覧 |
| `status` | LEDモード、UARTオーバーフローや割り込み回数など |
| `echo hello` | 引数を表示 |
| `print` | 出力テスト |
| `led on` / `led off` / `led blink` | オンボードLED操作 |
| `motor left forward 50` | 左モーターを正転、デューティ指定50 |
| `motor right reverse 30` | 右モーターを逆転、デューティ指定30 |
| `motor left stop` / `motor right stop` | 片側を停止 |
| `motor stop` | 両側のPWMを即時に0へ設定 |
| `drive forward 50` | 両輪を前進 |
| `drive reverse 50` | 両輪を後退 |
| `drive left 40` / `drive right 40` | 左右へ旋回 |
| `drive stop` | 両輪を段階的に減速して停止 |
| `drive forward 30 500` | デューティ30へ加速し、500ms後に減速開始 |
| `i2cscan` | I2Cデバイスのアドレス検索 |
| `distance` | 有効な最新距離と直近5回の移動平均、または診断情報を表示 |
| `gyro` | 識別値とXYZ角速度を1回表示 |
| `gyro 30` | 約100ms間隔で角速度を30回表示 |
| `gyro calibrate` | 静止中の200サンプルからゼロ点補正値を計算 |

数値は回転速度の測定値ではなく、PWMのデューティ指定です。50を指定しても最高回転数の半分になるとは限りません。小さい値ではモーターが始動しない場合もあります。

`drive`の指令では50msごとにPWMデューティを5ポイントずつ変更します。0から20へ約200ms、20から0へ約200msが目安です。逆転時は0まで減速してから逆方向へ加速します。

走行時間をミリ秒で指定すると、指令から指定時間後に減速を開始します。加速時間も指定時間に含み、完全停止までには減速時間が加わります。指定できる時間は0〜60000msです。`drive stop`は減速停止、`motor stop`は即時停止です。片輪を操作する`motor`指令は従来どおり即時にPWMを変更します。障害物検知・測距失敗による停止は加減速処理をキャンセルして即時にPWMを0へ設定します。
時間指定中はUART受信タスクが待機するため、別のコマンドによる途中停止はできません。距離による自動停止は動作します。短い時間から試し、緊急停止が必要な場合は電源を切れる状態で確認してください。

距離センサーの最新値が200mm以下になったとき、走行中の両輪を停止します。測距できない場合も停止します。センサーの値が200mmを超えるまで、前進・旋回・片輪の正転は受け付けません。後退は障害物から離れるために使用できます。距離が回復しても自動再発進はしません。測距は約100ms間隔のため、停止するまでに車体は動き続けます。最初の動作確認は車輪を浮かせ、低いデューティで行ってください。

### 両輪を前進させる例

最初は車輪を浮かせて回転方向と停止を確認してください。

```text
motor left forward 50
motor right forward 50
```

停止するときは、次を入力します。

```text
motor stop
```

`drive`コマンドは左右輪を続けて設定します。時間を省略した場合は、停止指令などで設定を変えるまで動作を続けます。

### 測距結果の有効性

距離はRangeStatusが有効な結果だけを採用します。`distance`が`invalid range`を表示するときの`raw`は採用しない生の距離、`raw_status`はレジスタ0x0089の下位5ビットです。ST ULDのAPIのRangeStatusとは番号が異なり、raw_status=9が有効（APIでは0）です。無効な結果は移動平均へ加えず、平均をリセットします。無効な測距や通信失敗は「前方が空いている」とは判定しません。

### ジャイロ表示とゼロ点補正

MPU-6050基板のVCCをPicoの3V3 OUT、GNDを共通GND、SDAをGP4、SCLをGP5、AD0をGNDへ接続します。VL53L1XとI²Cバスを共有します。XDA・XCL・INTは未接続です。

- `gyro`：識別情報とXYZの角速度を1回表示
- `gyro 30`：約100ms間隔で30回表示。車体を手で回して値を確認できます。

角速度の単位はmdps（1000 mdps = 1度/秒）です。角度ではありません。ジャイロレンジは±250度/秒で、`gyro calibrate`で静止時の偏りを補正できます。実行時にモーターを即時停止し、約1秒待ってから約2秒間、200サンプルの生データを平均します。補正後は各軸の生データから平均値を差し引き、角速度へ変換します。測定中は基板を動かさないでください。補正値はRAMに保持し、電源断やリセットで消えます。今回の基板は縦向きに取り付け、X軸が車体の上下方向を向いています。左右への旋回は主にX軸で測定します。取り付け向きを変えた場合は旋回軸も確認し直してください。連続表示中はUARTコマンド処理が待機するので、モーターを停止してから実行してください。距離測定と障害物停止は別タスクで継続します。

補正と確認の手順：

```text
gyro calibrate
# 約3秒間、基板・車体を動かさずに待つ
gyro 30
```

実機では補正前のX軸が約+1.2度/秒に偏っていました。補正後は0付近で正負に揺れる状態になり、静止時の偏りが減ることを確認しました。手で左右に回すとX軸の値が正負に反転しました。補正は角速度の偏りを減らすもので、絶対方位や旋回角を求める処理はまだありません。

## ソフトウェア構成

| ファイル | 役割 |
|---|---|
| `user/usermain.c` | 初期化とUART・LED・距離測定・モーター制御タスクの起動 |
| `user/command.c` | コマンド解析と各操作の呼び出し |
| `user/motor.c` / `user/motor.h` | 左右モーターの方向・デューティ設定・停止 |
| `drivers/pwm.c` / `drivers/pwm.h` | RP2040ハードウェアPWMの設定 |
| `drivers/i2c.c` / `drivers/i2c.h` | RP2040 I2C0ドライバ |
| `drivers/vl53l1x.c` / `drivers/vl53l1x.h` | VL53L1Xの初期化・測距・有効性判定 |
| `drivers/mpu6050.c` / `drivers/mpu6050.h` | ジャイロの読み出し・ゼロ点補正・角速度変換 |
| `drivers/uart.c` | UART0ドライバと受信割り込み |
| `user/task_uartrx.c` | 受信通知を待ち、コンソール入力を処理 |
| `user/uart_tx.c` / `user/task_uarttx.c` | 送信キューと送信タスク |
| `user/task_led.c` | 周期イベントとセマフォを使ったLED制御 |
| `user/task_distance.c` | 約100ms間隔の測距と5点移動平均 |
| `user/task_motor.c` | 50ms周期通知を受けて走行PWMを更新 |
| `kernel/cyclic.c` | 周期イベントの管理 |

アプリケーションで起動するタスクはUART受信・UART送信・LED・距離測定・モーター制御の5つです。
走行指令はUART受信タスクで目標値を設定し、モーター制御タスクでPWMを段階的に変更します。波形の生成はRP2040のPWMハードウェアが継続して行います。

```text
UART受信割り込み → イベント通知 → UART受信タスク → コマンド解析
                                     ├─ drive → モーター目標値
                                     └─ gyro → I²C → 角速度表示・補正

SysTick → 周期ハンドラ → セマフォ通知 → LEDタスク
        └─ 周期ハンドラ → セマフォ通知 → モーター制御タスク → PWM更新

VL53L1X → I²C → 距離測定タスク → 5点移動平均 → distanceコマンド
                         └─ 最新値・有効性 → 障害物停止・前進許可の判定
```

LED用の周期ハンドラは100msごとにセマフォを通知します。点滅モードでは10回分の通知を待ち、約1秒ごとにLEDを反転します。周期ハンドラは割り込み内で動作するため、通知だけを行い、LED操作はタスク側で実行します。

## テスト

```bash
make test-cyclic test-mutex test-motor test-range
```

周期イベント、ミューテックス、モーター制御、測距結果の有効性判定のホストテストです。モーターテストでは加減速・0を経由する逆転・障害物停止・測距失敗・停止後の再始動防止を確認します。割り込み・コンテキスト切り替えを模擬してカーネルのロジックを確認します。実際のSysTick割り込みやPWM出力、配線、モーター動作は検証しないため、実機確認も別途行います。

## 実機で確認したことと未確認のこと

- 車輪を浮かせた状態で、`drive forward`の加速と`drive stop`の減速を確認
- 測距値200mm以下で、加減速をキャンセルしてPWMが即時に0になることを確認
- VL53L1Xの距離に応じた表示と、5点移動平均の更新を確認
- ジャイロのWHO_AM_I=0x70、ゼロ点補正、手で左右に回したときのX軸の符号反転を確認

床上での加減速・停止距離、自律走行、ジャイロによる旋回角の計算・目標角度での停止は未実施です。PWMを0にしても車体は慣性で進むため、床上試験では停止距離を別途確認します。

## 今後の予定

- 補正済みX軸角速度から旋回角を計算
- 目標角度での旋回停止
- 床上での停止距離と旋回量の確認
- 左右の走行差の調整
- 距離センサーを使った障害物回避
